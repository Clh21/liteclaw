# LiteClaw v0.4 部署与服务鉴权设计

## 目标

让 LiteClaw 可以用单容器方式部署，同时为所有 `/v1` API 提供可选的服务级 API Key 鉴权。保持本地开发零配置可启动，容器示例默认要求显式密钥。

## 鉴权

新增 `LITECLAW_SERVER_API_KEY`。为空时关闭服务鉴权；非空时，所有 `/v1` 请求必须携带 `Authorization: Bearer <key>` 或 `X-API-Key: <key>`。两种方式同时提供且值不同视为认证失败。

密钥比较使用 `hmac.compare_digest`。失败统一返回 HTTP 401、`code=unauthorized` 和 `WWW-Authenticate: Bearer`，不区分缺失或错误。日志只记录状态码，不记录请求头或密钥。

`/health` 保持公开，供容器平台探针使用。OpenAPI 文档保持可读，但调用受中间件保护。本版本是单用户服务密钥，不实现用户身份、角色或资源隔离。

## 运行配置

CLI 新增 `LITECLAW_HOST` 和 `LITECLAW_PORT`，本地默认 `127.0.0.1:8000`。Compose 设置容器监听 `0.0.0.0:8000`，且保持单 worker，以符合 SQLite 与任务调度器约束。

## 容器

Dockerfile 使用 Python 3.11 slim，多阶段安装依赖和 Playwright Chromium，运行阶段创建非 root `liteclaw` 用户。应用位于 `/app`，持久化数据库位于 `/data`，助手文件工作区位于 `/workspace`。

Compose 挂载命名卷 `liteclaw-data:/data` 与本地 `./workspace:/workspace`，读取 `.env`，暴露 8000 端口，并通过公开 `/health` 做健康检查。容器使用 `restart: unless-stopped`。

`.dockerignore` 排除虚拟环境、Git、缓存、数据库、截图、测试缓存和本地密钥。

## 测试

- 未配置服务密钥时现有 API 保持可用。
- 配置密钥时，无凭据、错误 Bearer、冲突双头均返回 401。
- 正确 Bearer 与 `X-API-Key` 均可访问；`/health` 无需凭据。
- Settings 正确解析 host、port 和密钥，repr 不泄露密钥。
- Dockerfile/Compose 结构测试验证非 root 用户、单 worker、健康检查、数据卷和必需环境变量。
- 构建环境可用时执行 Docker build；若主机没有 Docker，则保留静态测试并明确记录限制。

## 完成标准

版本更新为 0.4.0，全部测试、ruff 和 pip check 通过；真实 HTTP 冒烟测试覆盖 401 和授权请求；README 与 DEMO 提供本地及 Compose 启动方式。

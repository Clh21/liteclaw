# LiteClaw v0.6 PostgreSQL pgvector 记忆索引设计

## 目标

v0.6 为长期记忆增加可选 PostgreSQL pgvector 索引，支持数据量增长后的服务端向量距离查询，同时保持 SQLite 为默认事实库和完整离线运行能力。

## 数据边界

sessions、messages、memories、runs、tasks、approvals 和 eval 数据继续写入 SQLite。pgvector 保存 memory id、文本、类型、重要性、embedding model 和向量副本，仅作为可重建的搜索索引。删除记忆时同步删除远端副本；启动连接成功后会把 SQLite 中已有 embedding 的记忆补齐到 pgvector。

配置 `LITECLAW_PGVECTOR_URL` 后启用。连接密码在 Settings repr、日志和 health 中都不返回。表名固定通过安全配置校验，默认 `liteclaw_memory_vectors`。启动会尝试 `CREATE EXTENSION IF NOT EXISTS vector` 和建表，失败时把状态标为 unavailable，主 API 继续启动。

## 检索与降级

HybridRetriever 仍先查询 SQLite FTS5。向量部分在 pgvector ready 时执行 cosine distance 查询，并与关键词结果用现有 RRF 融合。如果 PostgreSQL 请求失败，则本次查询立即退回 sqlite-vec；sqlite-vec 不可用时继续退回 Python cosine。远端结果只包含非敏感记忆字段，不读取或覆盖 SQLite 事实记录。

## 部署

新增 `compose.pgvector.yaml` 叠加文件，启动 pgvector 服务并向 LiteClaw 注入内部 URL。默认 `compose.yaml` 仍只有 LiteClaw，不要求 PostgreSQL。`asyncpg` 放在 `postgres` optional dependency 中；未安装时配置 pgvector 会显示 unavailable，而不会阻止应用运行。

## 边界

本版本不把完整业务数据库迁移到 PostgreSQL，不实现高可用、备份或跨节点一致性，也不创建维度固定的 HNSW/IVFFlat 索引。后续可根据实际 embedding 维度和规模增加索引迁移。

## 完成标准

安全表名、初始化、同步、upsert、删除、距离搜索、检索降级和 health 状态均有自动化测试；Compose 配置可解析；版本更新为 0.6.0；完整测试和静态检查通过。

# LiteClaw v1.1 多用户资源归属设计

## 目标

在 v1.0 角色鉴权之上增加数据隔离，使普通用户只能访问自己的会话及其派生资源，管理员保留跨用户管理能力。

## 归属模型

- sessions 增加 `owner_id`，由认证 Principal 自动写入。
- memories 增加 `owner_id`，自动抽取和显式写入均继承会话或当前用户。
- runs、approvals、browser state 和 scheduled tasks 通过 session 关系判断归属。
- eval 管理维持 admin 范围，避免共享回归案例泄露用户提示词。
- 旧数据 `owner_id=NULL` 只允许 bootstrap/admin 访问；关闭 RBAC 时维持原行为。

## 行为

- 越权读取统一返回 404，避免泄露资源是否存在。
- user/viewer 查询只返回自己范围的数据。
- admin 可指定或查看任意 owner，但 Token 和敏感字段仍不返回。
- 后台任务沿用创建任务的 session 归属，不依赖发起请求仍在线。

# LiteClaw v1.3 聊天记录工作台设计

## 目标

用户能在现有本地页面浏览已导入消息，按本地日历日期缩小分析范围，并把周报、月报、年报下载为带证据的 Markdown 文件。现有导入、归属、模型观察和报告 JSON API 保持兼容。

## 方案

1. 只在前端拼接报告：改动少，但不同客户端容易产生不同结果，且难以测试报告内容。
2. 由服务端复用报告分析结果生成 Markdown（采用）：一个纯函数渲染报告，API 返回下载内容；页面使用 Blob 下载。证据只取报告中的消息，不读取原导出文件。
3. 保存报告快照到数据库：便于历史版本，但增加敏感数据副本和同步问题，本版不做。

## 行为与接口

- 页面按选定来源每页显示 50 条消息，有上一页、下一页和当前页提示。来源改变后回到第一页；仍使用现有 owner 过滤的 `GET /messages`。
- 分析表单增加开始日期和结束日期，结束日期含当天。服务端以所选 IANA 时区把日期转换为 UTC 半开区间；如果也传旧版 `start_at`/`end_at`，返回 422，避免含糊的覆盖规则。结束早于开始返回 422。
- 新增 `POST /v1/chat-records/reports/markdown`，请求体与 `POST /reports` 相同；复用同一范围、owner、模型观察和证据结果。响应为 `text/markdown; charset=utf-8`，固定安全文件名。报告含周期、统计、本人完成事项、待核实事项、沟通观察和每条结论的证据原话；空项目明确写“无”。
- 页面保留最后一次报告请求，点击“下载 Markdown”时调用新接口。没有生成报告时禁用下载。令牌继续只存当前标签页。
- 不创建新的聊天内容持久化表，不读取微信数据库，不主动发送消息。配置外部模型时沿用 v1.2 的提示和数据范围。

## 验收

- 日期跨时区和包含结束日的边界测试；冲突输入和倒序日期返回 422。
- Markdown 内容含已完成事项、待核实事项与对应证据，按 owner 隔离；未授权访问不能下载他人的来源。
- 页面具备消息浏览、分页、日期过滤和下载控件。全量 pytest、Ruff 和脚本语法检查通过。

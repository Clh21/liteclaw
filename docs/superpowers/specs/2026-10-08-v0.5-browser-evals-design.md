# LiteClaw v0.5 浏览器状态与评测设计

## 目标

v0.5 让浏览器登录态在服务重启后可恢复，并把 Agent 的失败案例沉淀为可重复执行的评测。两项能力都服务于个人助手的长期运行：浏览器不必重复登录，功能更新也能用历史坏案例做回归。

## 浏览器状态

新增 `BrowserStateStore`，将 Playwright `storage_state` 按 LiteClaw session 保存到 `data/browser_state`。只有配置 `LITECLAW_BROWSER_STATE_KEY` 时才启用持久化；密钥必须是 Fernet URL-safe base64 key，并在配置 repr 中隐藏。状态文件只保存加密字节，文件名由受约束的 session id 生成。

`BrowserManager` 创建 context 时加载并解密状态，在 browser open、click、type 后保存，在关闭 context 前再次保存。解密失败或文件损坏时记录失败并创建干净 context，不让主服务启动失败。删除状态会同时关闭该 session 的 context，下一次使用从干净状态开始。

提供受现有服务 API Key 保护的状态查询和删除接口。接口只返回是否启用、是否存在和更新时间，不返回 cookie 或解密内容。

## Eval 数据与执行

SQLite 新增 `eval_cases`、`eval_runs`、`eval_results`。评测案例包含名称、prompt、可选的 `expected_contains` 和启用状态。一次评测运行按顺序执行选中的案例，每个案例创建独立临时 session，通过现有 `AgentRuntime` 完成真实 Agent loop，然后用大小写不敏感的包含判断给出 pass/fail。模型错误会记录为 error，并继续后续案例。

可从现有 agent run 创建回归案例，形成 bad case 回流。此操作复制最近一条用户消息作为 prompt；用户可以提供期望答案片段。评测历史永久保留，便于比较通过率。

## API 与页面

- `GET/POST /v1/evals/cases`
- `POST /v1/evals/cases/from-run/{run_id}`
- `POST /v1/evals/run`
- `GET /v1/evals/runs`
- `GET /v1/evals/runs/{run_id}`
- `GET/DELETE /v1/browser/sessions/{session_id}/state`
- `GET /evals` 返回静态仪表盘外壳，数据仍通过受鉴权的 `/v1` API 读取

仪表盘在浏览器 `sessionStorage` 中临时保存用户输入的服务 API Key，不把密钥写进 URL、HTML 或服务日志。页面支持查看案例、启动运行、查看最近结果和通过率。

## 边界

本版本不保存整个浏览器 profile，不同步跨设备状态，不处理 CAPTCHA，也不承诺所有网站的长期登录策略。评测只支持确定性的文本包含断言，不做 LLM-as-judge、并行执行或统计显著性分析。

# LiteClaw v0.3 SSE 实时事件设计

## 目标

为同步 Chat API 增加可选 SSE 实时接口，让客户端在 Agent 执行期间看到会话创建、模型步骤、工具调用、审批等待、最终回答和错误，而无需轮询。现有 JSON API 保持兼容。

## 接口

新增 `POST /v1/chat/stream`，请求体沿用 `ChatRequest`。响应类型为 `text/event-stream`，每个事件包含连续 `seq`、`type`、UTC `timestamp` 以及事件数据。

事件类型固定为：`session`、`run_started`、`model_started`、`model_completed`、`tool_started`、`tool_completed`、`approval_required`、`final`、`error` 和 `done`。`done` 始终是正常流的最后事件。错误在响应开始前仍使用标准 HTTP 错误；执行期错误使用 `error` SSE 事件。

SSE 数据使用单行 JSON，不直接拼接用户输入。每 15 秒无业务事件时发送注释心跳，防止代理连接超时。

## 组件

`app/core/events.py` 定义 `RunEventEmitter`，为单次请求分配序号并把字典事件送入回调。Runtime 的 `run`、`resolve_approval`、`_loop` 和工具执行路径接收可选 emitter；没有 emitter 时行为和开销基本不变。

`app/api/streaming.py` 定义 SSE 编码、队列桥接和 streaming 路由。路由创建后台 Agent task，生成器消费队列。客户端断开时不取消 Agent task，保证消息、run 和工具结果仍被持久化；队列仅存在于请求内，不承担恢复职责。

## 数据与隐私

流事件只包含必要字段。工具事件包含工具名、成功状态和耗时，不包含完整参数、密码或 token。最终事件包含完整回答和 usage。`run_id` 在 `run_started` 后提供；断线后的结果通过现有 `GET /v1/runs/{run_id}` 查询。

v0.3 不保存逐事件日志表，不承诺断点重放，也不模拟模型 token。真实 token 增量需要各模型适配器提供统一 streaming 接口，留到后续兼容版本；本版本交付真实的 Agent 步骤实时流。

## 审批

高风险工具触发时发送 `approval_required`，字段与同步 202 返回一致，然后发送 `done` 并关闭连接。客户端调用现有 approve/reject API；恢复结果仍可从该 API 的 JSON 响应和 run 查询获取。这样不会让 HTTP 连接无限等待人工输入。

## 错误和连接生命周期

后台 task 捕获模型认证、模型不可用、最大步数和未知异常，转成稳定错误码。SSE 生成器在 Agent 完成后退出。客户端提前断开只停止发送，不取消执行。应用关闭时 FastAPI 会按现有生命周期处理正在执行请求。

## 验收

- calculator 请求按顺序产生 session、run/model、tool、final、done。
- 普通回复不产生 tool 事件。
- 高风险工具产生 approval_required 且不执行工具。
- 模型错误产生 error 和 done，数据库 run 状态为 failed。
- 同步 `/v1/chat` 的响应和现有 53 项测试不变。
- SSE 响应头禁止缓存和代理缓冲。
- README、DEMO、版本号更新为 0.3.0。
